# Task Prioritization

> **Domain:** [[_software-engineering-moc|Software Engineering]]

## 🎯 Motivation

Deciding which tasks are most important. Urgent vs important, impact vs effort.

## 📋 Concrete Example

Prioritization: Fix security bug (urgent + important) = do now. New feature (important, not urgent) = next sprint. Change button color (not important) = maybe never. Focus on high-impact tasks.

## 🔗 Analogy

Task prioritization is like triage in an emergency room - the most critical patients (urgent + important) are seen first. Minor issues wait. Prioritization ensures the most important work gets done first.
