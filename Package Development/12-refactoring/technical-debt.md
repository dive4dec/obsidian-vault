# Technical Debt

> **Domain:** [[_refactoring-moc|Refactoring]]

## 🎯 Motivation

Technical debt is the hidden cost of quick-and-dirty solutions. Like financial debt, it accumulates "interest" — each future change takes longer because of earlier shortcuts.

## 📋 Concrete Example

Skipping tests to ship a feature fast is debt. Later, every change risks breaking something, and the time you "saved" is paid back with interest through slower, scarier updates.

## 🔗 Analogy

Using a credit card to buy now feels free, but interest compounds. The longer you wait to pay, the more expensive it gets — code shortcuts work the same way.
