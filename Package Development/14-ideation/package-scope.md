# Package Scope

> **Domain:** [[_ideation-moc|Package Ideation]]

## 🎯 Motivation

Defining what your package does — and does not do — keeps it focused and maintainable. A clear scope helps users set expectations and helps you say "no" to feature creep.

## 📋 Concrete Example

`timeflex` converts timetables to calendars. It does not send emails or manage contacts. Document this boundary in the README so users know to look elsewhere for those features.

## 🔗 Analogy

A pocketknife with a blade and bottle opener is handy. One with 50 tools is heavy and awkward. Knowing your knife's purpose keeps it sharp and useful, not bloated.
